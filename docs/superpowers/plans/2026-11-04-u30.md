# U30 (Umsatzsteuervoranmeldung) Implementation Plan

**Goal:** U30 in `@kreiseck/finanzonline`: prüfen, berechnen, XML bauen, senden (Standard `T`), Protokoll lesen.

**Architecture:** Reine, netzfreie Module unter `packages/finanzonline/src/u30/` (Katalog, Zeitraum, Berechnung, Prüfung, XML, Protokoll) plus ein dünner Client (`createU30`) über die bestehenden `createFileUpload` und `createDatabox`. Alle Beträge in Cent, Rechnung mit `BigInt`.

**Tech Stack:** TypeScript strict (CJS über `tsc`), `node:test`, `@kreiseck/finanzonline-core` (Session, SOAP, `parseXml`, Fehler), Dev-Abhängigkeit `xmllint-wasm@5.3.0` nur für Tests.

**Spec:** `docs/superpowers/specs/2026-11-04-u30-design.md` (Fakten: `docs/research/2026-11-03-finanzonline-inventar.md`)

## Global Constraints

- Node `>=20.18.0`; TS `strict` + `noUncheckedIndexedAccess`; keine Laufzeitabhängigkeiten.
- Deutsche öffentliche API; Beträge ganze Cent (`number`, `Number.isSafeInteger`).
- Standard `uebermittlung` = `T`; `P` nur bei `echt === true`; jeder andere `echt`-Wert → Fehler vor dem Netz.
- Innere XML-Deklaration exakt `<?xml version="1.0" encoding="iso-8859-1"?>`; Freitext nur U+0020–U+007E und U+00A0–U+00FF.
- Testdaten nur Ersatz: Steuernummer `911234565` (Melisse Nails e.U. / Livia Lindmayr). Keine echten Kennungen.
- Nichts an FinanzOnline senden; der Integrationstest überspringt sich ohne `FON_TID`, `FON_BENID`, `FON_PIN`, `FON_HERSTELLER_UID`, `FON_STNR`.
- Commits deutsch, Stil `feat(finanzonline): …` / `test(finanzonline): …` / `docs: …`, ohne Werkzeug-Hinweise.
- Tests: `npm test -w @kreiseck/finanzonline` (tsc → `test-dist`, `node --test`).

## Review Focus

1. Beträge als Kommazahl/String (`12.5`, `'1000'`) aus JS-Aufrufern → `BETRAG_KEINE_GANZZAHL`, nie gerundet. *(Task 3)*
2. KUNDENINFO mit Emoji/`€` (außerhalb Latin-1) oder Zeilenumbruch → `KUNDENINFO_ZEICHEN`, kein Senden. *(Task 3)*
3. Zeitraum um den Jahreswechsel in Wien (z. B. `jetzt` = 31.12. 23:30 UTC = 01.01. in Wien) → laufender Monat wird in Wiener Zeit bestimmt. *(Task 1)*
4. Protokoll mit unerwarteten Elementen (Produktionsformat unbekannt) → Parser wirft nicht, sammelt in `unbekannteElemente`. *(Task 5)*
5. `transport.retries: 3` vom Aufrufer → `sende` sendet trotzdem genau einmal. *(Task 7)*

**Files:**

**Interfaces:**
- Consumes: Task 1, Task 2 (`steuerFuerSatz`, `U30Kennzahlen`).
- Produces:
  - `type U30FehlerCode` = Union genau der Codes aus Spec 6 (inkl. `ERKLAERUNG_DOPPELT`).
  - `interface U30Fehler { code; nachricht; erklaerung?: number; kennzahl?: Kennzahl; feld?: string }`
  - `class U30PruefError extends FonError { readonly fehler: readonly U30Fehler[] }` (Nachricht nennt Anzahl und erste Codes).
  - `pruefeU30(paket: U30Paket, optionen?: { jetzt?: Date }): U30Fehler[]` — wirft nie; leeres Array = gültig.
  - `effektiveSatzNr(paket: U30Paket, index: number): number`, `effektiverUebermittler(paket: U30Paket): string | undefined` (für Task 4).

Regeln (exakt, fehlende Kennzahl = 0; Summen `s_bar = 000 + 001 − 021`, `s_frei = 011 + 012 + 015 + 016 + 017 + 018 + 019 + 020`):
- Paket: `paketNr` ganzzahlig 1…999999999; `erklaerungen` Array mit 1…9999; `uebermittler` (wenn gesetzt) wie Steuernummer, sonst müssen alle `steuernummer` gleich sein (`UEBERMITTLER_FEHLT`); `satzNr` (wenn gesetzt) ganzzahlig 1…999999999, effektive SatzNr eindeutig; Paar Steuernummer + `zrvon`/`zrbis` eindeutig.
- Steuernummer: `/^\d{9}$/`, Zahl 10000010…989999999, sonst `STEUERNUMMER_UNGUELTIG`; danach Luhn über alle 9 Stellen (von rechts jede zweite Ziffer verdoppeln, > 9 → −9, Summe % 10 === 0), sonst `STEUERNUMMER_PRUEFZIFFER`.
- Zeitraum: `zrVonBis` undefined → `ZEITRAUM_UNGUELTIG` (dann keine weiteren Zeitraum-/124-Prüfungen); `zrvon < '2022-01'` → `ZEITRAUM_NICHT_UNTERSTUETZT`; `jahr < Wiener Jahr(jetzt) − 5` → `ZEITRAUM_ZU_ALT`; `zrbis >= laufenderMonat(jetzt)` → `ZEITRAUM_NICHT_ABGESCHLOSSEN`.
- Kennzahlen: Schlüssel unbekannt → `KENNZAHL_UNBEKANNT`; Wert nicht `Number.isSafeInteger` → `BETRAG_KEINE_GANZZAHL`; `< 0` bei Typ ≠ `kzvorz` → `BETRAG_NEGATIV`; `|v| > 999999999999999` → `BETRAG_ZU_GROSS`. Bei einem dieser Fehler entfallen für diese Erklärung die BMF-Summenregeln und E2.
- BMF-Regeln: `kz000 === undefined` → `KZ000_FEHLT`; `s_frei > s_bar` → `STEUERFREI_UEBER_STEUERBAR`; `006+007+022+029+037+052+124 ≠ s_bar − s_frei` → `SUMME_STEUERPFLICHTIG_UNGLEICH`; `(065 > 0 || 071 > 0) && 070 === 0` → `IGE_OHNE_KZ070`; `071 > 070` → `KZ071_UEBER_KZ070`; `008+072+073+088+125 ≠ 070 − 071` → `SUMME_IGE_UNGLEICH`; Paare (066/057, 082/048, 087/044, 089/032): Vorsteuer > 0 und Steuerschuld 0 → `…_OHNE_…`, sonst Vorsteuer > Steuerschuld → `…_UEBER_…`; `020 > 0 && !vst` → `KZ020_OHNE_VST`; `vst && 020 === 0` → `VST_OHNE_KZ020`; `vst` nicht `/^[0-9][0-9,a-zA-Z]{0,3}$/` → `VST_UNGUELTIG`; `berichtigung && ueberschussVerwenden` → `ARE_BEI_BERICHTIGUNG`; `(124 > 0 || 125 > 0) && zrvon < '2026-07'` → `KZ124_125_ZU_FRUEH`.
- KUNDENINFO: mehr als 50 Zeichen (Codepoints) → `KUNDENINFO_ZU_LANG`; Zeichen außerhalb U+0020–U+007E, U+00A0–U+00FF → `KUNDENINFO_ZEICHEN`.
- E2: Schlüssel keine Satz-KZ → `ERWARTETE_STEUER_KEIN_SATZ`; Wert nicht ganzzahlig → `BETRAG_KEINE_GANZZAHL` (`feld: 'erwarteteSteuer'`); `≠ steuerFuerSatz(BMG, Satz)` → `STEUER_WEICHT_AB` (Nachricht enthält beide Beträge in Euro).
